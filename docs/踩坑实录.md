# 踩坑实录：四个坑，四天，一条命（32G 内存 3060 12G 训 Krea2）

> 时间线：2026-11-26 ~ 11-27，WorkBuddy 主控 + 多轮隔离实验排障。
> 写给同样想在小显存卡上训 Krea2 的道友——这些坑每个都搜不到现成答案。

## 背景

目标：把"2.5D 半写实 CG 写真"风格（57 张图）训成 Krea 2 风格 LoRA，用于短视频封面/插画。
硬件：RTX 3060 12G / 32G 内存 / Windows 11 / QLC 固态 C 盘。
训练器：ai-toolkit v0.13.43（Ostris），Krea 2 官方对口。

## 坑一：26G bf16 底座装不进 32G 内存

**现象**：训练卡在模型加载/量化阶段，内存磁盘 100%，显卡不动。可用内存 26G，"怎么算都够"，实际峰值要 29-30G（底座 26.3G + 运行时 2-3G + 系统占用）。Windows 拿硬盘当内存（页面交换），磁盘疯转。

**弯路**：等用户关掉一切程序，硬磨。量化是逐块做的，内存本该逐块下降，但峰值那一下就顶死。

**根修**：换 **Comfy-Org 官方 fp8 预量化底座**（12.2G，魔搭直连）。但直接换文件训练器不认——见坑二前置补丁（补丁 1）。

**教训**："模型文件多大，内存就要多大" 是错的，还要加运行时、系统占用；QLC 盘别拿来磨页面文件。

## 坑二：fp8 预量化文件"差一层窗户纸"

**现象**：fp8 底座下载完（12.2G），验文件头：键名与原版完全一致、fp8 权重 256 层带 scale_weight——但训练器不认。

**排查**：读 ai-toolkit 源码发现两套量化格式：
- ComfyUI **新版**格式：量化信息放在**文件头元数据**（`_quantization_metadata`）
- 训练器认的：每层自带 `{prefix}.comfy_quant` 标记张量

**关键发现**：训练器工具箱里有现成函数 `_markers_from_header`（文件头元数据 → 标记张量），通用加载入口 `_load_single_file` 会自动调用——但 **krea2 的加载器绕过了它、自己裸 `load_file`**，所以标记丢失，fp8 权重被当 bf16 全量展开（13G → 26G）。

**修复**：补丁 1，给 krea2 加载器补上 `_markers_from_header` 调用，复用官方现成函数。

**验证**：重启后日志打出 `Checkpoint is pre-quantized (float8_e4m3fn); keeping it`——上次卡死几十分钟的那关，30 秒全过。

## 坑三：显存空闲 10.8G，却报 CUDA OOM（最阴的一个）

**现象链**：开了内存管家（`layer_offloading`）后，编码器量化逐块 OOM——第 0~32 块成功、33 块开始全炸（疑显存碎片）；带防碎片开关重跑，第 2 块就炸；换 quanto 库也炸在最简单的 `torch.abs`（32MB）上。**显存空闲 10.79G，32MB 都申请不出来。**

**排查过程**（方法论：裸进程隔离实验逐一排除）：
1. torchao 单独测（fp32/bf16/真实层形状）→ 全过 ❌不是它
2. quanto 单独测 → 全过 ❌不是它
3. 纯进程占 20G 内存后测 CUDA → 正常 ❌不是内存耗尽
4. `PYTORCH_CUDA_ALLOC_CONF=expandable_segments` → Windows 官方忽略该配置 ❌
5. ai-toolkit 内部 `cuda_malloc.py` 强制 cudaMallocAsync → 无人导入，死代码 ❌
6. **最后锁定**：内存管家 `MemoryManager.attach` 把全部权重 **pin_memory 锁页**（12G 底座 + 4.5G 编码器 ≈ 16G）

**机制**：Windows 锁页内存走内核**非分页池**，有硬上限。打爆之后，该进程内**一切新的 CUDA 分配**——哪怕 32MB、哪怕显存空闲 10G——全部失败。这解释了所有"灵异现象"：单测全过（裸进程不锁页）、挂管家必炸（16G 锁页）。

**验证实验**：锁 14GB 锁页后裸进程测 CUDA → 正常（单次大块锁页不炸）；训练进程是"大模型加载中间夹杂几百次小锁页分配"，碎片化效应完全不同。

**修复**：补丁 4，环境变量 `AI_TOOLKIT_NO_PIN=1` 跳过全部锁页。**一次通过，训练正式进步数阶段。**

**教训**：Windows 上 "CUDA OOM" ≠ 显存不够。非分页池耗尽、WDDM 共享显存溢出都会伪装成 OOM。看到"显存空着还 OOM"，先怀疑锁页。

## 坑四：磁盘 100%、显卡时动时不动（性能坑）

**现象**：训练逻辑正常、loss 正常下降，但禁锁页后 17G 权重放在**普通可分页内存**里；32G 内存顶满后，Windows 把 9.3GB 权重页踢进页面文件 → 训练每取一层都要从硬盘读回来：磁盘 100%、显卡等数据、步速从 46s/it 恶化到 61s/it。

**修复**（两个开关，重启一次成功）：
1. `layer_offloading_transformer_percent: 0.8` —— 20% transformer 层常驻显卡（省 2.4G 内存 + 减搬运）
2. 重开 `cache_text_embeddings: true` —— 它早先崩溃的真因就是坑三的锁页；锁页修好后缓存一次成功，缓存完卸载编码器再省 4.5G 内存

**效果**：24s/it（快 2 倍多）、显卡利用率恒定 100%、页面文件 9.3G→2.9G、磁盘 100%→26%。

## 总结：32G 内存 + 12G 显存的生存法则

1. **底座用预量化 fp8**，别碰 bf16
2. **锁页是 Windows 上的头号杀手**，`AI_TOOLKIT_NO_PIN=1` 必带
3. **编码器量化留在 CPU**，别在训练进程里做 GPU 逐块量化
4. **20% 层常驻显卡 + 文本嵌入缓存**，把内存压到不分页
5. "CUDA OOM" 先查是不是别的东西伪装的，用 `torch.cuda.mem_get_info` 探针对质
