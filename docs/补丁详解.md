# 补丁详解：ai-toolkit v0.13.43 四处源码修改

> 全部改动已在 RTX 3060 12G / 32G 内存 / Windows 11 实机验证。
> 可手动照抄，也可用 `python scripts/apply_patches.py --ai-toolkit-dir <ai-toolkit目录>` 自动打（幂等，重复执行无副作用）。

## 补丁 1：krea2 加载器识别 ComfyUI fp8 预量化底座

**文件**：`extensions_built_in/diffusion_models/krea2/krea2.py`

**背景**：Comfy-Org 重打包的 `krea2_raw_fp8_scaled.safetensors` 把量化信息放在**文件头元数据**（`_quantization_metadata`）。ai-toolkit 通用加载入口会自动把它转成层标记（`_markers_from_header`），但 krea2 的加载器自己裸调 `load_file` 绕过了这一步——fp8 权重被当 bf16 全量展开（13G→26G），32G 内存机器必死。

**改动**：文件顶部 import 区加一行：

```python
# 借用官方 _markers_from_header 在读盘后补合成标记（复用 comfy_quant_import 全流程）。
from toolkit.models.v2._mixin import _markers_from_header
```

`_load_mmdit_state_dict` 内所有 `return load_file(...)` 改为包一层：

```python
    if name_or_path.endswith(".safetensors") and os.path.isfile(name_or_path):
        return _markers_from_header(name_or_path, load_file(name_or_path))

    if os.path.isdir(name_or_path):
        if filename is not None:
            path = os.path.join(name_or_path, filename)
            return _markers_from_header(path, load_file(path))
        candidates = [f for f in os.listdir(name_or_path) if f.endswith(".safetensors")]
        if len(candidates) == 1:
            path = os.path.join(name_or_path, candidates[0])
            return _markers_from_header(path, load_file(path))
        # ...（中间不变）
    return _markers_from_header(path, load_file(path))   # 函数末尾 hub 下载分支
```

**验证**：日志出现 `Checkpoint is pre-quantized (float8_e4m3fn); keeping it`。

## 补丁 2：内存管家模式下保留 TE 的 quanto 量化

**文件**：`toolkit/config_modules.py`（约 724 行附近）

**背景**：原代码在 `layer_offloading` 开启时把 `qfloat8`（quanto 后端）强转为 `float8`（torchao 后端）。torchao 在本机训练进程内逐层申请异常巨大显存（显存空闲 10.8G 仍 OOM），而 quanto 已实测 36 块全过。

**改动**：注释掉 TE 的强转（transformer 的强转保留——它对 fp8 底座无影响，因为配置里显式写了 `qtype: "float8_e4m3fn"`）：

```python
        if self.layer_offloading and self.qtype == "qfloat8":
            self.qtype = "float8"
        # [patch] 保留 TE 的 qfloat8(quanto)，不再强转 float8(torchao)：
        # torchao 在本机训练进程内逐块量化必炸（见踩坑实录坑三），quanto 已验证可用
        # if self.layer_offloading and self.qtype_te == "qfloat8":
        #     self.qtype_te = "float8"
```

## 补丁 3：编码器强制纯 CPU 量化

**文件**：`toolkit/models/v2/_mixin.py`（`aitk_quantize` 相关，约 389 行）

**背景**：量化默认把每块搬到 `quantize_device`（cuda:0）上算。在本机训练进程内，即使显存空闲 10.8G 也会 OOM（独立进程同样调用正常，疑为进程内状态与 WDDM 的兼容问题）。quanto 在 CPU 上量化已验证成功，只是稍慢，一次性成本可接受。

**改动**：在 `q_device = quantize_device if quantize_device is not None else device` 之后插入：

```python
            q_device = quantize_device if quantize_device is not None else device
            # [patch] low_vram（组件驻留 CPU）时强制纯 CPU 量化：
            # 训练进程内做 GPU 逐块量化会在显存空闲 10.8G 的情况下报 CUDA OOM
            # （独立进程同样的调用均正常）。quanto 在 CPU 上量化已验证成功（36 块全过）。
            if device is not None and torch.device(device).type == "cpu" and offload:
                q_device = None
                keep_on_device = False
```

**验证**：编码器量化 36 块全过、32 秒完成、零失败。

## 补丁 4：AI_TOOLKIT_NO_PIN 环境变量跳过全部锁页

**文件**：`toolkit/memory_management/manager_modules.py`

**背景**：`MemoryManager.attach` 会把全部权重 `pin_memory()` 锁页（12G fp8 底座 + 4.5G 编码器 ≈ 16G）。Windows 锁页内存走内核**非分页池**，有硬上限——打爆后进程内**一切新的 CUDA 分配**（哪怕 32MB、显存空闲 10G+）全部报 CUDA OOM。这是"显存空着却 OOM"的真元凶。

**改动 1**：文件头部（`if TYPE_CHECKING:` 块之后）加全局开关：

```python
# [patch] Windows 上对大模型全量锁页（pin_memory ≈ 12G 底座 + 4.5G 编码器）
# 会耗尽内核非分页池：之后进程内任何新的 CUDA 分配——哪怕几十 MB、显存空闲
# 10G+——都报 CUDA OOM。设 AI_TOOLKIT_NO_PIN=1 跳过全部锁页，H2D 走普通
# 分页内存（稍慢但稳定；配合 layer_offloading_transformer_percent 0.8 使用）。
_NO_PIN = os.environ.get("AI_TOOLKIT_NO_PIN", "0") == "1"
```

**改动 2**：三处锁页调用加门槛：

```python
        elif (
            isinstance(inner, torch.Tensor)
            and inner.device.type == "cpu"
            and not inner.is_pinned()
            and not _NO_PIN          # ← 加这行
        ):
```

```python
    if torch.cuda.is_available() and not _NO_PIN:      # ← _ensure_cpu_pinned 内
        try:
            t = t.pin_memory()
        except RuntimeError:
            pass
```

```python
                if torch.cuda.is_available() and not buf.is_pinned() and not _NO_PIN:  # ← 预取缓冲处
```

**验证**：带 `AI_TOOLKIT_NO_PIN=1` 启动，一次通过全部启动阶段，训练正式跑步数。

**注意**：禁锁页后权重放普通可分页内存，32G 内存机器必须配合配置里的 `layer_offloading_transformer_percent: 0.8` 和 `cache_text_embeddings: true`，否则权重会被 Windows 分页到硬盘（磁盘 100%、步速持续恶化）。
